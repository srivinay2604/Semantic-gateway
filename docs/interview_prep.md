# CacheGate Engineering Deep Dive & Interview Guide

This guide details the core design rationale, architectural tradeoffs, and operational mechanics behind CacheGate.

---

## 1. Why Cosine Similarity and Normalized Vectors? What Does HNSW Trade Off?

### Cosine Similarity & Normalization
Cosine similarity measures the orientation angle between two non-zero vectors in multi-dimensional space, defined as:
$$\text{CosineSimilarity}(u, v) = \frac{u \cdot v}{\|u\| \|v\|}$$

When embeddings are **L2-normalized** ($\|u\|_2 = 1$) upon inference:
$$\text{CosineSimilarity}(u, v) = u \cdot v$$
This reduces cosine similarity to a pure inner dot product, enabling SIMD vector operations (AVX-512) and fast BLAS matrix multiplications without per-comparison square root or magnitude computations.

### HNSW Tradeoffs
Hierarchical Navigable Small World (HNSW) is a multi-layer graph index for approximate nearest neighbors (ANN):
- **Recall vs Speed:** Exact flat search (FLAT) yields 100% recall with $O(N)$ linear scan latency. HNSW achieves 98%+ recall with $O(\log N)$ sub-millisecond search time.
- **Memory Overhead:** HNSW constructs a multi-layer graph where each vector stores bidirectional adjacency lists. In Redis Stack, HNSW requires additional memory per vector compared to raw vector storage.
- **Index Build Latency:** Inserting vectors into HNSW requires greedy graph routing and edge reconnection, making indexing slower than flat inserts. Because LLM cache writes happen asynchronously in the background, read-heavy workloads benefit dramatically.

## 2. How Was the Semantic Threshold Chosen? What Happens If It Is Too Low or Too High?

### Empirical Tuning Method
As documented in [`docs/benchmarks.md`](benchmarks.md), we ran an exhaustive parameter sweep (0.70 to 0.99) against our FAQ evaluation dataset containing positive paraphrases and hard negatives.

```
       Similarity Spectrum
0.0 --------- 0.85 --------- 0.92 --------- 1.00
 Unrelated     Hard Negatives  Production    Exact
               ("enable 2FA"    Threshold    Match
               vs "disable")   (0.0% FP)
```

- **If Threshold is Too Low (< 0.88):**
  - **False Hits:** Hard negatives trip the cache (e.g., *"How do I enable 2FA?"* matches *"How do I disable 2FA?"*).
  - **Hallucinated / Incorrect Instructions:** Users receive answers to opposing questions, severely damaging application trustworthiness.
- **If Threshold is Too High (> 0.96):**
  - **Cache Misses on Real Paraphrases:** Legitimate conversational variations (e.g. *"Reset password"* vs *"Recover my forgotten password"*) are missed.
  - **Hit Rate Collapse:** Semantic cache hit rate drops, forcing redundant upstream provider calls.
- **The Sweet Spot (`0.92`):**
  - **False-Hit Rate:** **0.00%** on our evaluation set.
  - **Recall:** **100.0%** on true conversational paraphrases.

## 3. How Do You Prevent a Semantic Cache from Returning Incorrect Responses Across Contexts?

CacheGate enforces **strict 5-tuple partition tags**:
1. `tenant_id`: Guarantees multi-tenant isolation. Tenant A never reads Tenant B's cached answers.
2. `model`: Prevents responses generated by `gpt-4o-mini` from being returned to callers requesting `gpt-4o` or `claude-3-5-sonnet`.
3. `sys_hash`: SHA-256 hash of system prompt and developer instructions. If System Prompt A specifies *"Answer in French"* and System Prompt B specifies *"Answer in Python code"*, they never share cache entries.
4. `params_hash`: Canonical hash of sampling parameters (`temperature`, `top_p`, `max_tokens`).
5. `ctx_hash`: Hash of prior conversational message history. Prevents conversational drift where identical prompts have completely different meanings depending on prior turns.

In RediSearch, this is implemented as an atomic tag query filter before vector KNN evaluation:
```
(@tenant:{customer_1} @model:{gpt-4o-mini} @sys_hash:{a1b2} @ctx_hash:{c3d4})=>[KNN 3 @vector $BLOB AS similarity]
```

## 4. Why Not Cache High-Temperature Requests?

In LLM sampling, temperature controls the sharpness of the probability distribution over candidate tokens:
- **Temperature = 0.0:** Deterministic greedy decoding or argmax sampling. The model returns the most likely token sequence every time.
- **Temperature > 0.3:** Stochastic sampling (nucleus / top-p). The caller explicitly desires creative diversity and non-deterministic variations.

Caching high-temperature responses defeats user intent (repeated calls returning identical static output instead of diverse variations) and pollutes cache capacity with transient responses. CacheGate enforces `CACHE_MAX_TEMPERATURE=0.3` by default.

## 5. What Is Cache Stampede and How Does Single-Flight Solve It?

### The Problem
When a popular cache entry expires or an unprecedented traffic surge hits a cold cache (e.g. 200 identical concurrent requests), all 200 concurrent requests miss the cache at time $t_0$. Without coordination, all 200 hit the upstream LLM API simultaneously, causing massive provider token spend, rate-limit 429s, and cascading gateway slowdown.

### The Single-Flight Solution
CacheGate combines two layers of coalescing:
1. **In-Process `asyncio.Future` Map:**
   - The first request creates a pending `Future` for the request hash key.
   - Subsequent identical requests in the same event loop find the existing Future and wait via `await asyncio.shield(fut)`.
   - The leader calls the provider, writes the result to cache, and sets `fut.set_result(response)`.
   - All waiting requests wake up immediately with the exact same response!
2. **Cross-Worker Distributed Redis Lock:**
   - For multi-process / multi-task deployments, the leader acquires `SET cg:v1:lock:{hash} token NX PX 10000`.
   - Followers poll the cache every 50ms until the leader completes the write.
   - Reduced upstream provider calls from **200 to 1** (99.5% reduction) in our benchmark.

## 6. Token Bucket vs Sliding Window: Why Use a Lua Script?

### Algorithm Comparison
- **Leaky Bucket:** Smoothes traffic to a rigid constant output rate; rejects legitimate short bursts.
- **Sliding Window Log:** Stores individual timestamps in Redis sorted sets (`ZADD`); memory consumption scales linearly with request volume.
- **Token Bucket:** Allows bursts up to bucket capacity $B$, then enforces steady refill rate $R$ tokens/second. Memory footprint is strictly $O(1)$ per key (stores only `tokens` and `last_updated_timestamp`).

### Why Lua?
In distributed environments, reading current tokens, checking if tokens $\ge 1$, calculating fractional elapsed time, and decrementing tokens requires multiple commands. A race condition between concurrent workers would cause over-allocation.
A Redis Lua script executes **atomically** on the Redis server without network roundtrips between checking and debiting tokens, preventing race conditions.

## 7. How Does the Circuit Breaker Work? What Are the Three States?

```
               Consecutive Failures >= 5
        +--------------------------------------+
        |                                      |
        v                                      |
    [ CLOSED ] --------------------------> [ OPEN ]
        ^                                      |
        |        Probe Succeeded               | Cooldown Expired (30s)
        +-------------------------------- [ HALF_OPEN ]
                                               |
                                               | Probe Failed
                                               +---------------+
```

1. **CLOSED (State 0):** Normal operation. Requests pass through to the provider. Consecutive failures are tracked.
2. **OPEN (State 2):** Upstream provider is experiencing an outage. Requests fail-fast in **< 1ms** with `503 Service Unavailable`, preventing connection exhaustion and resource starvation.
3. **HALF_OPEN (State 1):** After a 30-second cooldown, exactly one probe request is allowed through to test recovery.
   - If the probe succeeds: Circuit resets to **CLOSED** and traffic resumes.
   - If the probe fails: Circuit immediately trips back to **OPEN** for another cooldown cycle.

## 8. Why Adopt a Fail-Open Cache Policy?

Caching is an **optimization**, not the core business transaction. If Redis experiences a node crash or the local embedding model encounters an unexpected error:
- **Fail-Closed:** The gateway throws 500 Internal Server Error, taking down all client applications because an auxiliary cache is unavailable.
- **Fail-Open (CacheGate):** The gateway catches the cache exception, increments `cg_cache_errors_total{operation=...}`, logs a warning, and seamlessly forwards the request directly to the upstream LLM provider.

Client traffic continues uninterrupted, trading temporary upstream billing costs for 100% service availability.

## 9. How Would You Scale CacheGate to 10x / 100x Traffic?

1. **Decouple Embedding Inference to Dedicated GPU Workers:**
   - Currently, `all-MiniLM-L6-v2` runs in an async executor thread pool on CPU. At 10x traffic, move embeddings to a dedicated Triton or vLLM embedding cluster with batched TensorRT acceleration.
2. **Sharded Redis Cluster or MemoryDB:**
   - Transition from a single Redis Stack instance to AWS MemoryDB for Redis with multi-AZ read replicas and automatic partitioning.
3. **Chunk-Level Speculative Prefix Caching:**
   - Break incoming prompt turns into semantic chunks and perform prefix-tree matching to enable partial answer reuse for multi-turn conversational agents.
4. **Two-Stage Retrieval (ANN + Cross-Encoder Reranker):**
   - For sensitive domains, retrieve top-5 candidates via fast HNSW, then run a lightweight cross-encoder or classifier to verify semantic equivalence before returning cached output.
